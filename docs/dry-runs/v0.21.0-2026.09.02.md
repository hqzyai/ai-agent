## 方案可行性结论

流程骨架可行：不可变来源、版本映射、标准分支、语义冲突状态、治理检查和 acceptance 报告都按设计工作。正式发布仍有以下必需工作，未完成前 manifest 必须保持 `draft`：

1. 在持久 checkout 中按 specs 解决 42 个冲突，并审计约 2,427 个自动变更文件。
2. 将 AgentOS 的 Bot 契约迁入 v0.21.0 内置 Bot Mode，删除旧插件需有对应新测试，而不是直接选择一侧。
3. 把 `config/brand.env.example` 映射进目标源码与打包入口，证明一个非 AgentOS profile 也能通过配置生成；当前治理层已验证 profile 语法，但目标应用尚未消费这些变量。
4. 修复 contract audit 检出的 5 项回归，重新运行 quick/full acceptance。
5. 锁定合并 commit 后，才能在 Linux AMD64/ARM64 与 Linux/macOS/Windows runners 上构建 RC；三端新装、N-1 升级、回滚和人工验收仍不可由本次 macOS 源码演练替代。

GitHub Actions 运行 `candidate.yml` 还需要 `AGENTOS_SOURCE_TOKEN`；本次匿名 HTTPS clone 失败，已授权 SSH checkout 可以读取目标仓库。这项凭证要求应作为 runner preflight，而不是在构建中途发现。
