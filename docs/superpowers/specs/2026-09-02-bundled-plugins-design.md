# Bundled Plugins Design

## Goal

Make `ai-agent` the authoritative downstream source for AgentOS bundled plugins while preserving immutable provenance for the initial imports and keeping plugin integration testable across Hermes upgrades.

## Source boundaries

- Desktop plugins live under `apps/desktop/src/plugins/<plugin-id>/`.
- Hermes backend plugins live under `plugins/<provider-kind>/<plugin-id>/`.
- Imported files become first-class repository source. Future local changes do not require changing the external source repository.
- External repositories and archives are import inputs, never runtime dependencies and never automatically overwrite local changes.
- Generated bundles, IDE metadata, macOS metadata, nested delivery archives, secrets, and dependency caches are not committed.

## Provenance model

`config/bundled-plugins.lock.json` records:

- schema version;
- each bundle's stable id and type;
- authoritative local path;
- initial source URL/archive SHA and source commit/member path;
- imported file SHA-256 values;
- generated/excluded inputs.

The lock protects the declared snapshot. Updating a bundled plugin requires updating its source and lock in the same review. A validator rejects undeclared files, missing files, hash drift, path traversal, duplicate local paths, forbidden metadata, malformed manifests, and a residual `im-channels` identity.

## Release integration

The upstream-sync contributor workflow treats both plugin roots as downstream overlays:

1. Merge the exact Hermes release.
2. Reconcile upstream changes to the desktop plugin SDK and backend plugin interfaces.
3. Copy/reapply bundled sources into the product checkout without taking an external moving branch.
4. Apply or replace the `channels` integration patch.
5. Run plugin static, unit, integration, packaging, installation, and manual acceptance gates.

## Acceptance contract

Automated acceptance must verify:

- provenance lock integrity and safe paths;
- plugin manifest schema and required environment variable declarations;
- backend provider unit tests with external services mocked;
- Desktop TypeScript lint/typecheck/build against the locked Hermes SDK;
- `channels` registers the `/channels` route and sidebar contribution;
- onboarding start/status/apply/cancel behavior, including failure and expiration paths;
- missing credentials fail closed without leaking values;
- desktop packages include the compiled plugin and both architecture images include backend plugin source;
- the overlay patch applies cleanly or an explicit native-integration marker records why it is obsolete.

Manual acceptance uses the immutable candidate build and covers plugin discovery, default enablement, DingTalk/Weixin/QQ QR flows, cancellation, restart behavior, Qwen image/video generation, OpenSERP search, upgrade preservation, and uninstall/data retention.
